# 职称评聘问答助手 · 服务端方案（v2 已实施）

> 状态：**已实施**（2026-11-18）。评审决策：不限制数据访问范围；聊天记录按天存 md 日志（server/chatlogs/）；人设增加「所有回答以事实为准，不准猜测，回答不了就明说」。
> 选型记录：BFF 用 Node.js + TypeScript 同仓 `server/`；用户鉴权暂不做（内网直接用）。
> 实施验证：MCP 中继自检通过、/config 欢迎语下发、/models、代理链路、错误透传均实测通过；agent 循环的技能问答端到端验证因 GLM 账号 5 小时限额（当日 20:00 重置）暂缓，限额恢复后即可使用。

## 一、背景与目标

面向**山东医药技师学院**教师，做「职称评聘问答助手」，专门解释解答**教师职称评审和岗位竞聘**相关问题：

- 助手定位（人设）：**职称评聘小助手**，开场语「我是你的职称评聘小助手～很高兴为您服务，有职称评聘相关的问题随时可以问我哦。」
- API key、人设、skills、MCP 连接**全部配置在服务端**；老师打开页面直接问，无需任何配置；
- 能回答两类问题：**政策口径类**（读技能包里的办法条款、计分规则）和**分数排查类**（经 datacenter MCP 查现场库，按技能包的 SQL 模板逐项还原分数构成）。

## 二、已验证的技术结论（全部实测）

| 结论 | 证据 |
|---|---|
| GLM Anthropic 端点完整支持客户端工具循环 | `tools`(input_schema) → `tool_use`（流式 `input_json_delta`）→ `tool_result` 续答，天气工具闭环实测通过（2026-11-18） |
| GLM 端点不做 CORS | 预检无 ACAO 头 → 请求必须服务端转发 |
| datacenter MCP 中继链路可用 | 2026-11-18 实测：`query_site_platform_tool`（preview_table_data）→ DISPATCHED → `get_site_tool_operation` 轮询 → SUCCESS，`result.data.rows` 取数 |
| zcps-score-audit 技能包结构完整 | SKILL.md（含固定口径/红线）+ references×3（规则映射、SQL 模板、办法全文对照）+ scripts×3（整批测算） |
| GLM 忽略 DeepSeek 扩展字段；不支持 `latest_reminder` 角色 | 已在前端侧处理（改 user 消息注入） |

## 三、架构

```text
浏览器（chat-demo 前端，极小改动）
   │  SSE（Anthropic 兼容格式，同源）；启动时 GET /config 拉欢迎语
   ▼
BFF 服务端 server/（Express，端口 8787，生产时托管 dist/ 静态文件）
   ├─ GLM key/model（.env）
   ├─ persona.md（职称评聘小助手人设 + 开场语，替换前端 system）
   ├─ skills/zcps-score-audit/（解压自 zcps-score-audit.zip）
   ├─ MCP 客户端 → datacenter-mcp-d1abfe（HTTP + Bearer，192.168.1.103:8080）
   │     封装为 3 个精选工具（不是全量暴露）：
   │     · read_skill_file(path)      读技能参考文件
   │     · query_zcps_sql(sql, limit) 两步中继封装为同步调用，只读
   │     · get_table_schema(table)    查表结构（同链路）
   └─ Agent 循环：GLM ⇄ 工具执行 ⇄ 续答，多轮事件重写为单条 SSE 流
```

关键设计（沿用 v1）：

1. **BFF 对外暴露 Anthropic 兼容端点**，前端协议、流式渲染、历史记录全部复用。
2. **Agent 循环在服务端**，跨轮 SSE 事件索引连续化重写（抑制中间轮 `message_start`/`message_delta`/`message_stop`），前端 `streamMessage` 语义不变；各轮 thinking 块天然流式可见。
3. **前端"API Key"降级占位符** `'intranet'`，`GET /models` 恒 200。
4. **欢迎语不写死前端**：BFF 提供 `GET /config` 返回 `{ greeting }`（读 persona 配置），前端欢迎页文案启动时拉取、失败回退默认——助手定位保持在服务端配置。

## 四、MCP 接入细节

```json
// server/mcp.config.json
{
  "mcpServers": {
    "datacenter-mcp-d1abfe": {
      "type": "http",
      "url": "http://192.168.1.103:8080/mcp/d1abfe0ea170593d600892282ea81352",
      "headers": { "Authorization": "Bearer <token，移入 .env>" },
      "toolTimeoutSec": 600
    }
  }
}
```

- **两步中继封装**：`query_zcps_sql` 在 BFF 内完成 `query_site_platform_tool`(preview_table_data) → 轮询 `get_site_tool_operation`(waitSeconds=10) 直到完成/超时（600s），把 `result.data.rows` 直接返回给模型。模型只看到「给 SQL、拿行数据」的同步工具，不感知异步协议，出错路径大幅减少。
- **固定参数**（BFF 配置，不给模型）：siteId=`daddc818bd4648278aba2e1b51be06c9`（山东医药技师学院）、dataSourceId=`45632e9e579c4ebc822cca1df9e76dfd`（表单工作站，842 表，V_RSC_* 计分视图 + DA022_* 业绩表）。
- **只读红线**（技能包第 8 节）：`preview_table_data` 数据源天然只读；BFF 再加一道校验（仅允许 SELECT/WITH 开头、拒分号多语句），双保险；**不向模型暴露任何写类工具**（工单、ETL 执行、节点操作等 100+ 平台工具全部不出服务端）。
- **约束透传到工具描述**：limit≤100、11g 语法（ROWNUM 分页）、SQL 不加 schema 前缀、大结果需收窄——写进 `query_zcps_sql` 的 description，配合技能包 SQL 模板。
- **idempotencyKey**：每次调用生成唯一稳定键（BFF 内 UUID），重试复用同一键。
- BFF 必须部署在能访问 192.168.1.103 的内网。

## 五、Skills 装载

`zcps-score-audit.zip` 解压到 `server/skills/zcps-score-audit/`：

```text
skills/zcps-score-audit/
  SKILL.md                                     # 触发条件、输出格式、固定口径、红线
  references/rules-mapping.md                  # 单项↔视图↔表↔算法对应
  references/query-patterns.md                 # 各单项排查 SQL 模板
  references/计分规则对应关系(办法全文对照).md     # 办法条款全文对照
  scripts/build_queries.py · merge_final.py …  # 整批测算（离线工作流）
```

- **装载方式**：system prompt 注入技能清单（name + description + 文件列表）；`read_skill_file(path)` 工具按需读取 references 内容（路径白名单限制在 skills/ 内，防穿越；单文件截断阈值 ~64KB）。
- **scripts 不自动执行**：整批测算需要本地 Python + 当轮名单 Excel，属于评审季运维人员的离线工作流；v1 只作为参考文件可被 read_skill_file 读取（模型可指导人怎么跑），BFF 不执行任何技能内脚本。
- **年度维护**：技能包第 7 节要求每年评审季更新截止日期等口径——维护动作发生在服务端文件，改完即生效，无需动代码。
- 后续新增技能（如岗位竞聘政策包）按同样结构放 `skills/` 目录即可。

## 七、服务端结构

```text
server/
  package.json          # express、@modelcontextprotocol/sdk、tsx、typescript
  tsconfig.json
  .env                  # GLM_API_KEY、GLM_MODEL、PORT、MCP_URL、MCP_TOKEN（不入库）
  .env.example
  mcp.config.json       # datacenter MCP 连接（token 引 .env）
  persona.md            # 第六节草稿落地
  src/
    index.ts            # POST /v1/messages（agent 循环）、GET /models、GET /config、
                        #   /anthropic/v1/files 与 /v1/tools/* 透传（换 key）、托管 dist/
    config.ts           # 读 .env、persona.md、mcp.config.json、skills 清单
    upstream.ts         # 调 GLM（fetch + SSE 解析，AbortController 贯通）
    agent.ts            # system 替换（persona+技能清单）、剥离 deepseek 专属字段、
                        #   工具合并执行、tool_result 回传、SSE 索引连续化、
                        #   单工具超时 600s（MCP 中继慢）、最多 8 轮
    skills.ts           # 扫描 skills/*/SKILL.md、read_skill_file（白名单+截断）
    mcp.ts              # datacenter MCP 客户端：两步中继封装 query_zcps_sql /
                        #   get_table_schema，SQL 只读校验，idempotencyKey 管理
  skills/zcps-score-audit/   # 技能包（第五节）
```

## 八、前端改动（最小化）

- `rspack.config.ts`：`apiOrigin` 默认 `''`；dev 代理前缀指向 `http://localhost:8787`；`apiKey` 默认占位符 `'intranet'`。
- 欢迎页文案：启动时 `GET /config` 取 `greeting`，失败回退现有默认——「助手定位在服务端」的落地。
- 其余 src/ 不动（system 被服务端替换；deepseek tools 被服务端剥离）。

## 九、安全与治理（评审重点）

| 项 | 默认策略 | 待定夺 |
|---|---|---|
| 数据访问范围 | 内网全员可查任何教师的分数（技能包本为排查设计） | **是否限制教师只能查本人**？若限制需加用户身份（与「暂不鉴权」冲突，需权衡） |
| 写操作 | 一律不暴露（只读 SQL + 无写工具），修改建议人工走码表 | — |
| 敏感信息 | key/token 只在服务端 .env；会话仍存浏览器 IndexedDB（本地可见） | — |
| 查询留痕 | v1 不做 | 是否需要查询审计日志（谁查了谁）？ |
| 并发/限流 | v1 不做 | 内网范围小，暂可接受 |

## 十、已知限制

- 语音（ASR/TTS）透传 bigmodel，若无对应端点则语音功能报错，不影响文字会话。
- MCP 中继慢查询（600s 超时）期间前端只有 thinking 流可见，无进度提示；可后续在 thinking 块合成「正在查询数据库…」。
- 技能包 scripts 整批测算仍为离线人工流程。

## 十一、验证步骤

1. `npm --prefix server install && npm --prefix server run dev` 启动 BFF（8787）。
2. curl `http://localhost:8787/v1/messages`，问「张伟的表彰分是怎么算的」→ 期望：read_skill_file 读规则 → query_zcps_sql 出现 tool_use → tool_result 带回申报记录 → 最终回答含构成明细表（真实数据，先用测试问题验证链路即可）。
3. MCP 链路预检：BFF 启动时自检 `SELECT 1 FROM dual`（同本次实测），失败即拒绝启动并提示网络/权限。
4. 重启前端 dev server，浏览器 http://localhost:8090/：欢迎页显示小助手开场语；提问职称问题验证流式回复、thinking 展示、无需配置 key。
5. 越界测试：问非职称问题（应礼貌引导）、诱导改数据（应拒绝）、SQL 注入样例（只读校验拦截）。
6. `npm run type`、`npm run lint`、server typecheck 全过。
