# 已知数据现象：视图口径对部分人恒为 0（主档缺失）

核实日期：2026-11-24（现场库 user_dependencies / 实测查询）

## 什么是"岗位主档"（V_RSC_GWJP_JSXX，2026-11-24 读定义核实）

它不是教师基本信息表，而是**某个批次的职称评聘申报名册**：一行一个申报人，内容是姓名、工号、系列、
拟聘等级及其下一级等级、当前等级，以及两个关键年月（现等级取得时间、上一等级/资格时间，即任职年限的起算月）。

- 来源：职称评聘申报表 `DA129_ZCPS`，只取**一个固定批次**（流程期 `1e5a3fc0…`、表单类型 `72a63b1c…`）的申报单；不看审批状态。
- 两个年月里写死了约 33 个按工号的个别覆盖值（如 100115 → 2019-12、100258 → 2020-12），其余按申报表填写值推算。
  所以主档里的起算月可能与用户说的"起聘时间"不同（例：姜爽 100115，主档写 2019-12，聘任史末段是 2023-09）——遇到冲突按用户给定值算并声明。

## 现状数字（2026-11-24）

- 申报表共 121 条申报单；主档 **63 人**。
- 另有 **33 人**的申报单在另一个批次（流程期 `8d19ecd1…`）：27 条已审通过、5 条退回修改中、1 条草稿——他们不在主档，视图口径全为 0。
- 还有人现在库里已无申报单，例如 **李斐斐 100119**（在 2026-11-17 的 83 人摸底表里，序号 56）。
- **哪个批次是"本轮"尚未确认**：如果本轮评聘以另一批次或两批合并为准，计分视图指向的批次就不对，需要维护方处理。

## 现象

- 全部 53 个 `V_RSC_*` 计分视图都从岗位主档 `V_RSC_GWJP_JSXX` 出发（任职年限、党政管理、班主任、年度考核、论文、课题、表彰、成果转化等全部在内）。
- **不在主档里的人，所有视图项一律返回 0**，但其原始申报记录（`DA022_*` 表 + `ss_process`）是完整的。

## 排查时的正确做法

1. 先看 `get_score_detail` 返回的 `register`（或 `item=all` 里的 `viewGap: true`）。
2. 主档无此人 → 视图项为 0 是预期现象，**不要排查视图定义**（实测一次要烧掉约 9 轮工具调用，把轮次预算耗尽）。
3. 用原始表复算：党政管理用 `work_history`（`DA022_T_JS_GZJL`），考核优秀用 `annual_review`/`term_review`，学历用 `education`（`V_RSC_XL` 不依赖主档），业绩用各 `_RY` 模板。

## 验证样例（李斐斐 100119，起聘 2023-09，截止 2026-10-31）

- 党政管理：中层副职 2015-03~2022-04 → 中层正职 2022-05 至今（两段相接须合并）；起聘后 38 个月 × 2.4/12 = **7.60**（摸底基准 7.60）
- 考核优秀：年度考核 2020 优秀、2024 优秀，起聘后仅 2024 一次 × 2 = **2.00**（基准 2）
- 学历：本科 + 学士，`V_RSC_XL.SCORE` = **4**（基准 4）

## 尚未解决

- 班主任 / 历史班主任分目前只有视图口径（摸底基准李斐斐为 1.10 + 0.70），没有验证过的原始表复算模板——主档缺失人员的这两项暂时只能标"待核"。
