# 职称评审分数排查（zcps-score-audit）

回答"XX 的 XX 分怎么来的"这类问题。核心原则：**每个分数都能落到「办法条款 → 计分视图 → 业绩申报表原始记录」三层证据上**，不接受"视图算出来就是这么多"这类无明细的回答。

## 0. 输出格式（固定）

1. **构成明细表**：该单项的每条来源记录（名称/等级/时间/审批状态/计分），合计对上被问的分数；
2. **计分依据**：引用《量化办法》条款（分值表）+ 库内实现（视图名）；
3. **结论/差异原因**：若与某版本数字不一致，明确指出是哪一层的差异（数据未申报 / 审批未过 / 窗口外 / 口径不同 / 规则特例）。

## 1. 先读参考文件

- 单项 ↔ 视图 ↔ 底层表 ↔ 算法的完整对应关系：读 `references/rules-mapping.md`
- 各单项现成的排查 SQL 模板：读 `references/query-patterns.md`
- 办法条款↔视图↔表的全文对照：读 `references/计分规则对应关系(办法全文对照).md`（自包含副本；仓库 docs/ 下有同名源文件）

## 2. 数据库访问（必须走职称评审 MCP，不要直连数据库）

计分视图和业绩数据在**山东医药技师学院现场平台**上，通过总台职称评审 MCP（datacenter-mcp）中继查询，已实测打通：

**固定参数**：
- siteId：`daddc818bd4648278aba2e1b51be06c9`（山东医药技师学院）
- 数据源：表单工作站 `45632e9e579c4ebc822cca1df9e76dfd`（842 表，含全部 `V_RSC_*` 计分视图和 `DA022_*` 业绩表；其余数据源：本应用=APPLICATION_DATASOURCE、data_lq=67e606e45c88460b92e7243d7d82efdf）

**调用链**（两步，中继是异步的）：
1. `mcp__datacenter-mcp-d1abfe__invoke_mcp_tool`，name=`query_site_platform_tool`，
   arguments={siteId, idempotencyKey: 每次调用唯一稳定键(8-128位), name: `preview_table_data`, arguments: {dataSourceId, customSql: "SELECT ...", limit: 100}}
2. 返回未完成(DISPATCHED)时，用返回的 operationId 调 `get_site_tool_operation` 轮询（waitSeconds=10），结果在 `result.data.rows`

**约束**：
- `preview_table_data` 只读，`limit` 最大 100；大结果用 WHERE 收窄或分页（11g 语法，`ROWNUM<=n`，不支持 FETCH FIRST）
- customSql 里**不要加 schema 前缀**（如 `WORKFLOW_SDYYJS.`），现场数据源直接访问对象名即可：`SELECT * FROM V_RSC_GWJP_JSXX WHERE ROWNUM<=5`
- 查表结构用现场原生工具 `get_table_schema`（同链路，arguments={dataSourceId, tableName}）；列数据源用 `list_datasource`
- **取数一律走本中继，禁止用 oracle/oracle-intern MCP 直连作为数据源**：直连的 179 实例是开发库，且混杂 `WORKFLOW_CS_*`、`WORKFLOW_CS_LDZY*` 等其他学校的测试 schema（同名表/视图装的是外校数据），极易串库查错人；仅在用户明确要求比对开发库时才可对照，且必须由用户指定 schema

## 3. 排查流程

### 3.1 定位人（重名必核对工号/部门）

已知重名：张伟（100019 离退休处 / 100107 男 药品商贸学院）、王艳（100013 大 图书馆 / 100149 小 基础部）。用户只给姓名时，先查名单确认工号再往下走。名单来源优先级：
1. 当轮摸底/报名名单文件（用户提供的 Excel）；
2. 库 `DA129_ZJGWJP`（旧岗位竞聘报名）/ `DA129_ZCPS`（新申报）；
3. `V_RSC_GWJP_JSXX`（注意其中 200121/100258/100265/100032 四人的聘任起始月是**人工硬编码**的，与名单可能不一致，需向用户声明）。

### 3.2 定位分项并取原始记录

按 `references/rules-mapping.md` 找到该项的底层表，套用 `references/query-patterns.md` 的 SQL（已内置审批/窗口条件），查出该人的全部原始申报记录。

### 3.3 复算并对比

用记录套办法分值（或码表 `ZJB_RSC_DM` 的 fz）重算，与被问的数字对比。对不上时按第 4 节清单归因。

## 4. 固定口径（所有排查默认遵守）

| 项 | 口径 |
|---|---|
| 审批 | `ss_process.process_status‖process_result = 'FINISHAGREE'`，在办/草稿/驳回一律不计 |
| 业绩窗口 | 起聘月 `rdsj` < 业务时间 ≤ 当轮截止（2026 轮：业绩/任职年限 **2026-10-31**，教学工作量/学生管理 **2026-06-30**；以当轮名单脚注为准） |
| 任职年限 | 月 ×0.1（含首尾月：`MONTHS_BETWEEN(截止,起聘)+1`），截止=当轮年限截止日 |
| 默认 0 项 | 教学评价、学工考核、岗位工作考核、服务质量考核、民主测评、领导评议（评议类当轮未开展按 0；取历史值须用户明说） |
| 考核等次为空 | 培训/继教管理等按**系数 1**计（库视图口径），不要当 0 |
| 党政管理 | `V_RSC_JZGZ` 截止月取 `annual_review_info`（code_=ZCPS、当年）`max(END_TIME)` 所在月（2026 轮=**2026-09**，非办法业绩截止 10-31，也非工作量截止 6-30）；起算用 `rdsj_up` 且**含起聘当月**（办法口径不含）。两版本差 0.2=中层正职一个月（2.4/12）。实例：100111 视图 14.05（副职 23 月×1.8/12=3.45 + 正职 53 月×2.4/12=10.6，截止 2026-09）；算到 2026-10 则 14.25 |
| 表彰 | 校2/市局委4/厅8/省12/国16；通报表扬减半；**同一年度同一类别只取最高**，跨年度可累计 |
| 论文限篇 | C/D/E 每人最多 2 篇（取分数最高两篇）；B 类及以上不限 |
| 纵向课题 | 正高申报校级不计；副高校级限 2 项；主持人到账经费每满 1 万 +2 分（自筹不计）；基础分查码表 |
| 教材 | 非规划教材每人限 2 部；主审=同级别第一主编减半；字数不足 2 万按字数/2万折算 |
| 横向课题 | 必须通过"技术服务合同"认定（sftgjdhys='是'）才计 |
| 专利 | 发明4/实用·外观2/软著1 × 位次系数（1/0.8/0.5 或 1/0.7）；限项数视图未实现，需人工核 |
| 码表 | 纵向课题/成果奖/教材奖/教学实践项目/职业能力提升/指导学生竞赛的分值都在 `ZJB_RSC_DM`（lx/jb/hjdj/wc/lb → fz），改分值不改代码 |
| 职业能力权重 | `ZJNLTS.QZ` 现场**按百分数录入**（50/80/100），复算时 QZ>1 按 ÷100 换算，否则出天量分（曾出 1770） |
| 竞赛/实践项目 | 得分视图对竞赛**逐条全额累计，不做每项 10 分封顶**（办法上限未在视图实现）；世赛教练型选手可累计出几十分（实测 ZZGS2026 来庆专 19 条已批=228.11，数据真实），交付时须标注"未封顶，建议按办法封顶后使用" |
| 历史班主任月份 | `BZRDB_LS` 的月份映射取**学年首年**（2023-2024 学年三月→2023-03），春季月份被系统性前置；起聘后第一学年的三~六月会被窗口误排除，发现该情况按自然年（+1 年）重核并向用户声明 |

## 5. 常见"0 分 / 差异"原因清单（按命中率排序）

1. **没申报或没批完**：查 `ss_process` 状态（DRAFT/ING/BACK/REFUSE）——教材奖、成果转化曾整类全军覆没于此；
2. **窗口外**：业绩/任职在起聘之前（继教管理、党政协程常见），或晚于截止日；
3. **限项/取最高**：同年同类别表彰、C/D/E 论文、非规划教材、副高校级课题、同赛项多奖；
4. **认定缺失**：横向课题未做技术服务认定；
5. **码表未配**：`ZJB_RSC_DM` 缺对应 lx/jb/hjdj/wc 组合 → NVL 0 分；
6. **口径差异**（无对错，需用户定夺）：名单起聘 vs 库聘任区间算法（`ZCPS_YSFJG.A1`，截止 2028-10、含跨档累计）；评议类置 0 vs 取库值（`ZCPS_YSFJG` 的 EA/EB/EC 列）；
7. **默认 0 项**：评议类六项本轮置 0，库里可能有历史值但不用。

## 6. 整批测算（收编脚本）

单点排查之外的整批分数测算用 `scripts/` 三步完成（详细用法见 `scripts/README.md`）：

1. `python scripts/build_queries.py <名单.xlsx> <工作目录>` —— 生成 b1~b7 批量 SQL（轮次参数在其顶部 CONFIG）；
2. 会话内经职称评审 MCP 中继逐个执行（`preview_table_data`，customSql=SQL 内容），结果 rows 存为 `b1.json~b7.json`（大结果按 nextOffset 拼全）；
3. `python scripts/merge_final.py <名单.xlsx> <工作目录> <输出.xlsx>` —— 合并生成 v9 版式测算表（含合计校验）。b7 的 zynl 已内置 QZ>1 按÷100 换算，无需后处理。

## 7. 年度维护（每年评审季更新一次，用户已确认此策略）

次年使用前需更新：`scripts/build_queries.py` 顶部 CONFIG 与 `scripts/merge_final.py` 的 RZ_CUTOFF（截止日期）、本文件第 4 节固定口径表中的当轮默认值（截止日/默认 0 项）、第 3.1 节重名清单。名单用当轮新文件。逾期未改时，凡与当轮实施方案脚注不一致的口径，以脚注为准并向用户声明。

## 8. 提醒与红线

- **写 SQL 前先确认列名**：本文件与 query-patterns.md 里的 SQL 模板列名是实测过的（如 V_RSC_GWJP_JSXX→zgh/xm，DA022_T_JSJBXX→c_zgh/c_xm/c_ssbm），**禁止凭感觉猜列名**；query_zcps_sql 连续失败 2 次必须停下，改用 get_table_schema 查表结构或回读模板——现场平台把 SQL 错误包装成笼统的「执行失败，请检查参数」，不代表参数没传到，更不代表接口故障；
- 视图名在活跃变更：`V_RSC_GWJP_FS_*`→`V_ZCPS_FS_*`、`V_RSC_JCJ`→`V_RSC_KY_JCJ` 的更名**已同步到正式库**（2026-11 经职称评审MCP核实，旧名已删、新名生效；单项计分层仍为 V_RSC 原名）；后续升级仍可能改名，遇"对象不存在"先按新前缀在 `all_views` 搜别名，别误判成数据没了；
- 修改数据**一律不做**：MCP 只读；改分值建议走码表，向用户说明后由人工操作。
