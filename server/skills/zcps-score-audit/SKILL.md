# 职称评审分数排查（zcps-score-audit）

回答"XX 的 XX 分怎么来的"这类问题。核心原则：**每个分数都能落到「办法条款 → 计分视图 → 业绩申报表原始记录」三层证据上**，不接受"视图算出来就是这么多"这类无明细的回答。

## 0. 输入口径与回答纪律（最高优先级，测算前必读）

1. **参数优先级：用户显式给定 > 会话背景记忆 > 本文件固定口径 > 库值。** 起聘月、截止日、竞聘等级等，用户说了就按用户的算。用户值与库值或默认口径冲突时，**仍按用户值测算**，并在回答开头声明两处来源（例："你给定起聘 2023-09，库内聘任记录为 XXX，本表按你给定值计算"）；禁止静默采信另一个值，更禁止把库里捞到的值当成"已确认"覆盖用户输入。
2. **测算前先做等级映射并写明**：专技 1-4 级=正高（zgj）、5-7 级=副高（fgj）、8-10 级=中级（zj）、11-12 级=初级（cj）。等级影响限项规则（如纵向课题：正高申报校级不计、副高校级限 2 项）。
3. **默认动作不请示**："继续补查剩余单项""把明细列全"是本分，直接做完再交卷；不要向用户发"方案一/方案二"式的选择题，也不要让用户提供你查得到的东西。即使工具轮次用尽，也要交出"已确认项明细 + 已确认项小计 + 待核项清单"，不要请用户回复"继续"。
4. **过程不进答案**：SQL、轮询、报错、字段比对是内部过程，最终回答只含明细表、办法依据、结论与差异；内部草稿（含未验证的中间数字）不得混入正式回答。**取数必须发起真实工具调用，绝不在正文中书写任何工具调用标记或伪调用文本（如 DSML/XML 调用块）**——需要什么数据就调什么工具，正文里出现调用标记即是错误。**需要调用工具的那一轮不要输出任何说明或推理文字（中英文都不行），直接发起调用；所有输出一律使用简体中文。**
5. **查不完也要出表**：已核实单项正常列出，未完成单项标注"待核"及原因，出**部分结果表**；不得以"数据不全"为由拒绝出表，更不得为凑全表编数——宁可留待核空位，不可编一个数。

## 0.2 测算 / 核对某人分数：必用 `calc_raw_score`，不要自己算

只要问题是"算一下 / 核对 / 测算某人的分数或总分"，**所有分数一律以 `calc_raw_score` 的输出为准**。**"某一项分是怎么来的"这类追问同样如此：先调 `calc_raw_score` 取分，再用 `get_score_detail` 列记录**——某一轮没调算分工具、照着记录自己按公式算，虽然数算对了，却把属于工作量分的"党政管理"说成了"基础分、上限 15"。某一项属于哪一类、上限多少，也只能照 `calc_raw_score` 的结果说。它用与摸底测算完全相同的算法，从库内审批通过的申报记录算出各单项、各类小计和总分（原始分 + 按办法上限封顶后）。**禁止自己心算、手算、按分值表逐条加总或"估算"任何一项**——同一份原始记录，模型自算曾三次给出三个不同的数。

**入参怎么填**（people 每人）：
- `zgh` 工号：必填。
- `rdsj` 起聘月、`level` 拟聘等级：用户给了就原样传（格式由工具规范，如 2023-9 会处理成 2023-09）。
- `postSeq` 岗位序列、`series` 系列：**用户没说就不传**。这是摸底名单上的事实，不是可以替用户猜的口径——名单里有此人时以名单为准，传了不同的值只会得到一条提示。
- 用户没给的先不传：工具会从摸底名单自动回填，并在返回的"入参来源"里注明（user / roster / default）。工具报"缺少…"时，把缺的几项一次问全，不要替用户假设，也不要先出分。
- `name`：用户给了姓名就一并传，用于核对工号有没有输错。

**截止日期**：默认用本轮参数（见返回的 config）。**只有用户当前这句话里明确说了截止日期才传 `config`**。业绩截止、教学工作量截止、任职年限截止是**三个独立的口径**：用户说"业绩认定截止 X"时只传 `cutoffYeji`；`cutoffGzl`（教学工作量/学生管理截止，默认 2026-06）和 `rzCutoff` 只有用户明确提到对应事项时才传。服务端会拿用户原话逐项核对，对不上会报错，此时按报错提示修正后重新调用。

**回答怎么写**：
1. 开头一行写明口径：起聘月、截止日期、岗位序列，以及每项是用户给的、取自摸底名单还是默认值（照工具返回的"入参来源"写）。用户给的和库内不一致时仍按用户值算，并声明。
2. 出完整明细表（各大类 → 各单项 → 小计），照工具输出填，不改数、不自行四舍五入。
3. 给两个总分：原始分总分（不封顶，与摸底表同口径）和封顶后总分（按办法各类上限），并列出被截断的类别。与摸底测算表是否一致，照工具返回的"摸底表对比"写（本次改过截止日期时它为空，就不要对比）；**不要引用、推算或编造"上次""之前""另一版本"的分数来对比。**
4. 工具结果里的"回答要求"是硬性纪律，逐条照办（模型不一定每次都读了本文件，所以关键纪律同时放在工具结果里）。
4. 要解释"某一项由哪些记录构成"时，再用 `get_score_detail` 取该项的原始申报记录。**只列记录（名称、时间、等级、审批状态），分数写引擎给的该项合计；不要自己给每条记录标分，也不要写出自己的加总算式**——引擎只给单项合计，逐条的取舍规则（窗口、同年同类取最高、限篇、位次系数）靠读记录是算不准的，曾出现"自己加出 16 分、引擎是 10 分"的矛盾表述。记录清单与你理解的规则对不上时，只写"该项合计 X 分"，不要解释成你算的那个数。
5. 工具返回的"提示"（如姓名与工号不一致、起聘月晚于截止月、你传的岗位序列与名单不符）必须原样告知用户。工具执行失败时不出的数就不要出，如实说明。
6. **不说没有在本次对话里查到过的库内情况**。例如"库内主档对某工号另有硬编码值""远高于同类任何人"这类判断，没有查询依据就不要写；需要这类判断就先查，查不到就不说。觉得某项分数异常时，可以只陈述事实并建议人工核对原始记录（例如"实践项目与大赛 193.80 分，数值很大，建议核对原始申报记录"），不要下"明显异常""高于所有人"这类没有依据的结论。

## 0.5 输出格式（固定）

1. **构成明细表**：该单项的每条来源记录（名称/等级/时间/审批状态/计分），合计对上被问的分数；
2. **计分依据**：引用《量化办法》条款（分值表）+ 库内实现（视图名）；
3. **结论/差异原因**：若与某版本数字不一致，明确指出是哪一层的差异（数据未申报 / 审批未过 / 窗口外 / 口径不同 / 规则特例）。

**已知数据现象——视图口径对部分人恒为 0**：全部 53 个 `V_RSC_*` 计分视图都从"岗位主档" `V_RSC_GWJP_JSXX` 出发。岗位主档不是教师基本信息，而是**一个固定批次的职称评聘申报名册**（申报表 DA129_ZCPS 中属于指定流程期的申报单）。不在主档里的人——申报单在其他批次的（2026-11 实测 33 人）、或库里已无申报单的（如李斐斐 100119）——所有视图项都返回 0，**但原始申报记录是完整的**。遇到 `item=all` 返回里的 `viewGap: true`，或视图项为 0 而 `register` 也为 0 行时：这是预期现象，**不要去排查视图定义**，直接用 `work_history`（党政管理）、`annual_review`/`term_review`（考核优秀）、`education`（学历）和各业绩原始表的结果复算。

**调用链**（两步，中继是异步的）：
1. `mcp__datacenter-mcp-d1abfe__invoke_mcp_tool`，name=`query_site_platform_tool`，

## 5. 常见"0 分 / 差异"原因清单（按命中率排序）

1. **没申报或没批完**：查 `ss_process` 状态（DRAFT/ING/BACK/REFUSE）——教材奖、成果转化曾整类全军覆没于此；
2. **窗口外**：业绩/任职在起聘之前（继教管理、党政协程常见），或晚于截止日；
3. **限项/取最高**：同年同类别表彰、C/D/E 论文、非规划教材、副高校级课题、同赛项多奖；
4. **认定缺失**：横向课题未做技术服务认定；
5. **码表未配**：`ZJB_RSC_DM` 缺对应 lx/jb/hjdj/wc 组合 → NVL 0 分；
6. **口径差异**（无对错，需用户定夺）：名单起聘 vs 库聘任区间算法（`ZCPS_YSFJG.A1`，截止 2028-10、含跨档累计）；评议类置 0 vs 取库值（`ZCPS_YSFJG` 的 EA/EB/EC 列）；
7. **默认 0 项**：评议类六项本轮置 0，库里可能有历史值但不用。

## 6. 整批测算（收编脚本）

单点排查之外的整批分数测算用 `scripts/` 三步完成（详细用法见 `scripts/README.md`）：

1. `python scripts/build_queries.py <名单.xlsx> <工作目录>` —— 生成 b1~b7 批量 SQL（轮次参数在其顶部 CONFIG）；
2. 会话内经职称评审 MCP 中继逐个执行（`preview_table_data`，customSql=SQL 内容），结果 rows 存为 `b1.json~b7.json`（大结果按 nextOffset 拼全）；
3. `python scripts/merge_final.py <名单.xlsx> <工作目录> <输出.xlsx>` —— 合并生成 v9 版式测算表（含合计校验）。b7 的 zynl 已内置 QZ>1 按÷100 换算，无需后处理。

## 7. 年度维护（每年评审季更新一次，用户已确认此策略）

## 8. 提醒与红线

- **写 SQL 前先确认列名**：本文件与 query-patterns.md 里的 SQL 模板列名是实测过的（如 V_RSC_GWJP_JSXX→zgh/xm，DA022_T_JSJBXX→c_zgh/c_xm/c_ssbm），**禁止凭感觉猜列名**；query_zcps_sql 连续失败 2 次必须停下，改用 get_table_schema 查表结构或回读模板——现场平台把 SQL 错误包装成笼统的「执行失败，请检查参数」，不代表参数没传到，更不代表接口故障；
- 视图名在活跃变更：`V_RSC_GWJP_FS_*`→`V_ZCPS_FS_*`、`V_RSC_JCJ`→`V_RSC_KY_JCJ` 的更名**已同步到正式库**（2026-11 经职称评审MCP核实，旧名已删、新名生效；单项计分层仍为 V_RSC 原名）；后续升级仍可能改名，遇"对象不存在"先按新前缀在 `all_views` 搜别名，别误判成数据没了；
- 修改数据**一律不做**：MCP 只读；改分值建议走码表，向用户说明后由人工操作。
